## 🌳 Зачем нужны ветки в Git?

Представь, что в команде три человека работают над одним сайтом: один делает авторизацию, второй — дизайн, третий — корзину покупок.
Если все будут писать код прямо в `main`, они непрерывно будут ломать код друг друга.

**Ветка (`branch`)** — это изолированная параллельная линия разработки:
1. Ты ответвляешься от `main` (например, создаёшь ветку `new`).
2. Спокойно экспериментируешь и делаешь коммиты.
3. Когда фича готова — вливаешь (`merge`) ветку обратно в `main`.

---

## 💥 Что такое Merge Conflict (Конфликт слияния)?
Конфликт возникает, когда в ветке `main` и в ветке `new` **одновременно изменили одни и те же строки в одном и том же файле**.
Git не может угадать, какая версия правильная, и просит разработчика:
```
<<<<<<< HEAD (текущая ветка main)
PORT = 3000
=======
PORT = 8080
>>>>>>> new (вливаемая ветка)
```
Разработчик вручную удаляет маркеры `<<<<<<<`, `=======`, `>>>>>>>` и оставляет нужный код, после чего делает коммит слияния.

## 🚦 Уровни заданий

### 🟢 Уровень 1: «С нуля» (Базовый)
1. Создать ветку: `git checkout -b new` (или `git switch -c new`).
2. Создать файл `feature.txt` и сделать коммит.
3. Вернуться в `main`: `git checkout main`.
4. Влить ветку: `git merge new`.

### 🟡 Уровень 2: «Практик» (Методичка кафедры ЦАТ)
1. Создать ветку `new`, добавить файл `data.txt`, сделать коммит.
2. Вернуться в `main`, создать файл `data.txt` с тем же именем, но другим содержимым, сделать коммит.
3. Выполнить `git merge new` — поймать конфликт слияния!
4. Открыть `data.txt`, удалить маркеры конфликта, сохранить результат.
5. Завершить слияние коммитом: `git add data.txt && git commit -m "Resolve merge conflict"`.
6. Сохранить граф коммитов: `git log --graph --oneline > graph.txt`.

### 🔴 Уровень 3: «Профи» (Бонус методички)
1. Создать от `new` ветку `new2`.
2. Сделать 2 коммита и откатить последний через `git revert HEAD`.
3. Влить `new2` в `main` через `git rebase` вместо merge.
