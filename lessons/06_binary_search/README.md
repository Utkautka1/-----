## 🔍 Интуиция бинарного поиска: почему он такой быстрый?

Представь телефонный справочник на 1 000 000 фамилий.
- **Линейный поиск ($O(n)$)**: листать страницу за страницей от первой до миллионной. В худшем случае потребуется **1 000 000 проверок**.
- **Бинарный поиск ($O(\log n)$)**: открыть справочник ровно посередине. Если искомая фамилия «правее» — мы **за один шаг отбрасываем сразу 500 000 страниц**! На следующем шаге отбрасываем 250 000, затем 125 000...
Для диапазона из **1 000 000 чисел** потребуется максимум **20 шагов**!
А для **1 000 000 000 чисел** — всего **30 шагов**!

---

## 📐 Ключевые требования практической работы СПбГУПТД

1. **Поиск без выделения памяти**:
   Категорически запрещено создавать список всех чисел диапазона `list(range(a, b + 1))`! Поиск выполняется исключительно математически по границам `left`, `right`, `mid`.
2. **Формула середины**:
   ```python
   mid = (left + right) // 2
   ```
3. **Сдвиг границ**:
   - Если `mid < x` (ищем правее): `left = mid + 1` (потому что `mid` уже проверен!).
   - Если `mid > x` (ищем левее): `right = mid - 1`.
4. **Теоретический максимум шагов**:
   $$n = b - a + 1$$
   $$\text{max\_steps} = \lceil\log_2(n + 1)\rceil = \text{math.ceil(math.log2(n + 1))}$$
